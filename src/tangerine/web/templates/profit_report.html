{# The two-lens P&L table (#114) — the reason the screen exists. Two adjacent rows put the cash-basis lens (what actually left the bank) beside the recipe-cost lens (what should have been consumed), each with its % against the same revenue base. This is the *only* surface the two-lens panel appears on (regression-guarded above); Period and Month stay recipe-cost-only. The two lenses disagree by design — a big Makro restock shows a healthy recipe-cost GM but a thin (or negative) cash-basis GP, the beans will sell later but the cash has already left. Surfacing both honestly is the whole point; the panel never picks a winner. Percentages are computed in-template against the shared revenue, matching ``tangerine.margin.gross_margin_pct``'s 2dp quantisation (None when revenue is zero — no division by zero, no misleading "0%"). #} {% set ns = namespace(cash_pct=none, recipe_pct=none) %} {% if report.tiles.revenue != 0 %} {% set ns.cash_pct = (report.tiles.cash_basis_gp / report.tiles.revenue * 100) | round(2) %} {% set ns.recipe_pct = (report.tiles.recipe_cost_gm / report.tiles.revenue * 100) | round(2) %} {% endif %}

The two lenses answer different questions and disagree by design — recipe-cost GM costs what should have been consumed (at as-of- date prices), cash-basis GP costs what actually left the bank. A big restock month shows a healthy GM beside a thin (or negative) GP; the beans will sell later, but the cash has already gone.
